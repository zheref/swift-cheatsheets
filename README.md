# Swift Interview Cheat Sheets

29 dense cheat sheets — SwiftUI, TCA, Swift concurrency, Combine, timing operators,
collections, SOLID, functional Swift, Clean Code, engineering practices, iOS architecture,
modularization, testing, algorithms and complexity, streaming/time-series patterns,
AI-assisted workflows, atomic file I/O, and Core Bluetooth — including seventeen
hand-laid-out SVG infographics.

Designed to be opened on a second screen (iPad, phone, laptop) and skimmed while you code:
sidebar navigation, instant full-text search, syntax-highlighted snippets, dark/light
themes, and a responsive layout that collapses to one column on small screens.

A **language selector** in the top bar lists Swift, TypeScript, Kotlin and C#. Switching
keeps you on the same concept where the other language has it, and says so plainly where it
does not. Only Swift is published today; the other three are listed as *not yet published*
until their catalogs land (zheref/swift-cheatsheets#3).

The site is built with **Gatsby 5 + TypeScript + Chakra UI 3** from a **content catalog
kept as data** (YAML), so another language is a new catalog folder, not a new page.

- **No build step required to read it** — `index.html` is committed: one self-contained
  file (no CDN, no fonts, no network) that works opened from disk, AirDropped, or in Files.
- **A build step to change it** — edit `content/`, then `npm run build` regenerates the
  Gatsby site (`public/`) and the offline `index.html`.

## Quick start

```bash
npm ci                 # Node 22.22+ or 24.15+ (see .nvmrc)

open index.html        # just read it — the committed offline file

./serve.command        # or build and serve the site to every device on your Wi-Fi
```

`serve.command` prints both URLs it is listening on:

```
  This Mac : http://localhost:8000/
  iPad etc : http://192.168.1.42:8000/
```

Open the second URL on your iPad, phone or other laptop. **Type the `http://` prefix
explicitly** — modern browsers upgrade bare addresses to HTTPS, which a plain HTTP server
cannot answer.

## Serving over the local network

### Option A — plain HTTP (simplest)

```bash
./serve.command          # port 8000
./serve.command 8080     # custom port
```

Requirements:

- Both devices on the **same Wi-Fi network** (not a guest network, and no VPN active on
  either device — a VPN routes traffic away from the LAN).
- macOS may ask to allow **node** to accept incoming connections the first time.
  Approve it, or the other device will simply time out.
- If macOS Firewall is on: *System Settings → Network → Firewall → Options* and allow
  incoming connections for node.

### Option B — HTTPS (when the browser refuses HTTP)

Some browsers force every address to HTTPS and will not fall back. The symptom is
`ERR_SSL_PROTOCOL_ERROR` on the client.

```bash
./serve-https.command        # port 8443
./serve-https.command 9443   # custom port
```

This generates a throwaway self-signed certificate in `.localcert/` (git-ignored) with the
correct `subjectAltName=IP:<your-ip>`, which Safari requires, and regenerates it
automatically if your Mac's IP changes. The first visit shows a certificate warning:

- **Safari** → *Show Details* → *visit this website* → *Visit Website*
- **Chrome / Edge** → *Advanced* → *Proceed to … (unsafe)*

### Option C — no server at all (offline)

`index.html` at the repository root is the **offline artifact**: the Swift catalog
server-rendered into one file with its styles, data and a small script inlined. AirDrop it
to the iPad and open it from **Files**, or double-click it. Navigation, search, snippets,
diagrams and the theme toggle all work with no network — and it reads fully even with
JavaScript off. It is regenerated by `npm run build` (or just `npm run build:offline`),
and CI fails if the committed copy is stale.

### Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `ERR_SSL_PROTOCOL_ERROR` | browser forced HTTPS on a plain HTTP server | type `http://…` explicitly, or use `./serve-https.command` |
| Connection times out | firewall, different subnet, or an active VPN | approve the macOS firewall prompt; disable VPN; confirm both devices are on the same SSID |
| `EADDRINUSE` | a previous server is still running | `lsof -ti :8000 \| xargs kill`, or pick another port |
| `public/index.html is missing` | the site was never built | `npm run build` |
| Browser keeps redirecting to HTTPS | cached HTTPS-upgrade for that host:port | use a different port, an incognito window, or turn off Chrome's *Always use secure connections* |

## Editing the content

Everything on the page comes from `content/` — there is no HTML to hand-edit.

```bash
npm run develop   # live-reloading dev server on http://localhost:8000
npm run build     # Gatsby site into public/, offline file into index.html
npm run verify    # structural checks on both built pages
npm test          # parity, rendering, hydration and offline tests
npm run check     # what CI runs, except its committed-index.html staleness check
```

The `Makefile` keeps the familiar shortcuts (`make`, `make build`, `make verify`,
`make serve`, `make serve-https`).

### Adding a card

Open the sheet's YAML file in `content/languages/swift/sheets/` and add an entry under
`cards:`. Five kinds exist:

| `kind` | Renders | Fields |
| --- | --- | --- |
| `code` | one syntax-highlighted snippet | `code`, optional `expected` |
| `compare` | side-by-side columns | `columns: [{label, tone, code}]`, optional `expected` |
| `rules` | a colour-coded bullet list | `items: [{tone, text}]` |
| `table` | a comparison table | `headers`, `rows` |
| `diagram` | a full-width SVG infographic | `svg`: a file in the catalog's `diagrams/` |

Every card has an `id` (stable, kebab-case, unique in its sheet), a `title` and a `note`,
and may carry `concept`, `applies` (platforms, runtime, requirements, versions) and
`sources`. `tone` is `good`, `bad`, `modern`, `legacy` or `neutral`. Rule and table text
supports `` `inline code` `` and `**bold**`.

```yaml
  - id: derived-binding
    kind: code
    title: Derived binding
    note: Wrap get/set when the view needs a different shape than the model.
    code: |-
      let upper = Binding(
        get: { name.uppercased() },
        set: { name = $0.lowercased() }
      )
```

Use a literal block (`|-`) for code so Swift backslashes and generics survive verbatim;
React escapes everything at render time. Quote YAML scalars that would otherwise parse as
booleans or null (`"true"`, `"null"`) — the schema refuses them with the file and field.

### Adding a sheet

1. Create `content/languages/swift/sheets/<id>.yaml` with `id`, `concept`, `scope`,
   `title`, `group`, `subtitle` and `cards`.
2. Add `<id>` to `sheets:` in `content/languages/swift/language.yaml` — that order controls
   both the sidebar and the scroll order. Sheets sharing a `group` must be adjacent.
3. `npm run build && npm run verify`.

**A sheet's `id` is its page anchor** (`index.html#<id>`). Never rename one: saved links
depend on it.

### Adding a diagram

Diagrams are plain SVG files in `content/languages/<lang>/diagrams/`, 940 units wide
(`viewBox="0 0 940 H"`, `class="dg"`), coloured only through the theme's CSS custom
properties (`fill="var(--modern)"`, `stroke="var(--good)"`…) so they follow light and dark
mode. Diagrams are injected as raw markup, so the loader checks them against an
**allowlist**: plain drawing elements (`svg g defs marker path rect line polyline polygon
circle ellipse text tspan title desc`), presentation attributes only, double-quoted values,
no `style`, no `href`, no numeric entities, and `url(#id)` as the only reference. Anything
else — a script, a handler, an external reference, a non-numeric `font-size`, a different
width — fails the build with the file named.

### Adding a language

See [docs/CONTENT-MODEL.md](docs/CONTENT-MODEL.md). In short: a new folder
`content/languages/<id>/` with a `language.yaml` (route, highlighter keywords, sheet order)
and its sheets, listed in `content/registry.yaml` — the selector's languages, in order. Give
sheets the same `concept` as their equivalents in other languages so switching lands on them.
No template, component or route code changes.

### Project layout

```
swift-cheatsheets/
├── index.html                 generated — the offline artifact (committed), one self-contained file
├── content/registry.yaml      the languages the selector offers, in order
├── content/languages/swift/   the Swift catalog: language.yaml, sheets/*.yaml, diagrams/*.svg
├── src/
│   ├── content/               renderer-independent: schema, loader, highlighter, inline markup, search
│   ├── ui/                    framework-neutral React + Chakra: the page, cards, theme, hooks
│   ├── adapters/gatsby/       the Gatsby page template (thin)
│   ├── adapters/offline/      the offline renderer and its browser entry (thin)
│   └── pages/404.tsx
├── gatsby-node.ts             one page per published catalog, at its declared route
├── gatsby-ssr.tsx / gatsby-browser.tsx   provider wrap and the pre-paint theme script
├── scripts/                   build-offline.mts, verify.mts, serve.mts (+ Hatsu CI scripts)
├── test/                      vitest suite and fixtures (legacy inventory, a four-language fixture site)
├── serve.command              HTTP server for LAN access
└── serve-https.command        HTTPS server (self-signed) for TLS-forcing browsers
```

`npm run verify` checks both built pages: one section per listed sheet in order, every
sidebar link resolves, groups are adjacent, no raw markup leaked into a code block, diagram
font sizes are numeric, no serialisation artefacts, the language selector lists the registry
in order with this language current and every language link landing on a built page, and
the offline file references no external resource at all.

## Keyboard shortcuts

| Key | Action |
| --- | --- |
| `/` | focus the search box (it searches the current language only) |
| `Esc` | clear the search, close the drawer, unfocus — or, inside the language list, close it |
| Language button | open the language list; `Tab` through it, `Enter` to switch |
| `☼` button | toggle dark / light (remembered per browser) |
| `☰` button | show the sidebar on narrow screens |

## Requirements

- **Node.js 22.22+ or 24.15+** (`.nvmrc` says 24; Gatsby 5.16 supports up to 25, jsdom 31 needs
  22.22+/24.15+) and npm. Dependencies are pinned exactly in
  `package-lock.json`: Gatsby 5.16.1, React 19.2.9, Chakra UI 3.38.0.
- **openssl** — preinstalled on macOS; only used by `serve-https.command`.
- Any modern browser. Rendering uses `color-mix()` and CSS cascade layers —
  Safari 16.4+, Chrome 111+.
