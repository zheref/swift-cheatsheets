### Added

- **Twenty required aspects, a template for new languages, and a test that holds every catalog to them.** [`content/aspects.yaml`](content/aspects.yaml) lists what each published catalog covers — UI layers (programmatic and declarative), styling, state management, structured concurrency, async flows, timers and scheduling, networking (REST, SOAP, gRPC, GraphQL), video streaming, security and authentication, accessibility, localization, serialization, collections and strings, unit and integration testing, UI and end-to-end testing, architecture, clean code, SOLID, functional programming and modularization — each with the checklist a sheet must answer. `node scripts/new-language.mts <id> <Name>` scaffolds a catalog with one stub sheet per required part; its output is committed as `templates/new-language/`, and [docs/ADDING-A-LANGUAGE.md](docs/ADDING-A-LANGUAGE.md) walks through the rest. A catalog that lacks a part needs a waiver giving the reason the topic does not exist there.
- **Examples can import real libraries.** The example runner resolves pinned, example-only libraries — `examples/package.json` for TypeScript (RxJS, Redux Toolkit, React, SolidJS, jQuery and others), `examples/kotlin/jars.txt` for Kotlin (Maven coordinates with each jar's SHA-256, fetched by `npm run examples:install`) and `examples/csharp/packages.json` for C# — so a library example is compiled and run like any other. A TypeScript example can be a React `.tsx` file that runs, or a Solid one that is type-checked. The site's own dependencies are unchanged.
- **The TypeScript catalog covers every required aspect.** It grows from 10 sheets to 41 (423 cards): React, SolidJS and jQuery side by side, Chakra UI and Tailwind styling, Redux, Redux Toolkit and MVVM stores, RxJS and its timing operators, timers and workers, REST, SOAP, gRPC and GraphQL, HLS and DASH playback, security, accessibility, localization, serialization, strings, UI and end-to-end testing, architecture, clean code, SOLID, functional programming and modularization. 293 of its 329 examples are compiled and run on every pull request; the rest name the browser or application host they need. Its coverage sheet now maps almost every Swift sheet to a TypeScript counterpart. Nothing that was published before was removed.
- **Thirteen new Swift sheets, added among the original 29, which keep their relative order.** UIKit — Programmatic UI; SwiftUI — Styling, Design Tokens & Theming; MVVM — View Models, Bindings & Observation; RxSwift — Core; Strings; Serialization; UI & End-to-End Testing; Security, Authentication & Privacy; Accessibility; Localization & Internationalization; Networking — REST with URLSession; Networking — SOAP, gRPC & GraphQL; and Video Streaming — HLS & AVPlayer (164 cards). Every snippet was type-checked against the iOS SDK in Swift 6 mode and each sheet was swept by an independent reviewer. The 29 original sheets are byte-identical and keep their anchors; the TypeScript, Kotlin and C# coverage sheets gain a row for each new topic.
- **The C# catalog covers every required aspect.** It grows from 10 sheets to 36: .NET MAUI in XAML and in C# code, WPF and WinUI, Blazor, the three compared, styling and themes, unidirectional state, Rx.NET and its timing operators, timers, REST, SOAP, gRPC and GraphQL, video streaming, security, accessibility, localization, serialization, strings, UI and end-to-end testing, architecture, clean code, SOLID, functional C# and project modularization — plus deeper algorithm, streaming, file and testing sheets. Every runnable example is compiled and run on every pull request, on Linux; XAML, Blazor and device examples name the application host they need and were compiled outside the runner while they were reviewed. No workflow runs on Windows. Every card that was published before is unchanged, except the coverage sheet's matrix, whose rows now point at the new sheets.
- **The Kotlin catalog covers every required aspect.** It grows from 11 sheets to 35: Jetpack Compose layout, lists, navigation and animation, Android Views in code, the two compared, Material theming, MVVM and MVI, Flow timing operators, timers, REST with Ktor, OkHttp and Retrofit, SOAP, gRPC and GraphQL, Media3 video, security, accessibility, localization, serialization, strings, UI and end-to-end testing, architecture, clean code, SOLID, functional Kotlin and Gradle modularization — plus deeper algorithm, streaming, file and testing sheets. Its runnable examples are compiled and run with `kotlinc` on JDK 21 wherever that toolchain is installed (CI does not run them); Android examples name the app host they need and were compiled against the Android SDK and AndroidX while they were reviewed. Every card that was published before is unchanged, except the coverage sheet's matrix, whose rows now point at the new sheets.
- **What an example build may pull in is pinned by content.** A C# example's NuGet restore is checked, package by package and transitive ones included, against the SHA-512 recorded in [`examples/csharp/packages.lock.json`](examples/csharp/packages.lock.json) before anything builds (`npm run examples -- --lang csharp --write-nuget-lock` records it after the allowlist changes). The build itself now gets a scratch `HOME` and none of the caller's environment, as a running snippet already did, because a package's MSBuild targets and source generators run inside it. A Kotlin jar is used only when `examples/kotlin/jars.txt` names it and its SHA-256 still matches; a stray or altered jar stops the Kotlin examples instead of being compiled against. `examples/.npmrc` turns lifecycle scripts off for the example libraries on every machine, not only in CI.
- **`npm run examples -- --sheets <ids>` and `--content <dir>`** run the examples of chosen sheets, or of a catalog kept outside `content/`. A sheet id no catalog has a file for, or a flag given without its value, is refused (exit 2) instead of running nothing and passing.

### Changed

- **The Swift catalog can grow.** Its parity test now holds the 29 original sheets byte-identical and in their original relative order, and lets new sheets be added among them, instead of pinning the catalog to exactly those 29.
- **The "most examples are run" bar is held where an example can run.** More than 80% of the examples on language and shared-concept sheets must be executed; an example on a platform sheet (a UI framework, a media player, a device API) that cannot run names the application host it needs.
