### Added

- **Twenty required aspects, a template for new languages, and a test that holds every catalog to them.** [`content/aspects.yaml`](content/aspects.yaml) lists what each published catalog covers — UI layers (programmatic and declarative), styling, state management, structured concurrency, async flows, timers and scheduling, networking (REST, SOAP, gRPC, GraphQL), video streaming, security and authentication, accessibility, localization, serialization, collections and strings, unit and integration testing, UI and end-to-end testing, architecture, clean code, SOLID, functional programming and modularization — each with the checklist a sheet must answer. `node scripts/new-language.mts <id> <Name>` scaffolds a catalog with one stub sheet per required part; its output is committed as `templates/new-language/`, and [docs/ADDING-A-LANGUAGE.md](docs/ADDING-A-LANGUAGE.md) walks through the rest. A catalog that lacks a part needs a waiver giving the reason the topic does not exist there.
- **Examples can import real libraries.** The example runner resolves pinned, example-only libraries — `examples/package.json` for TypeScript (RxJS, Redux Toolkit, React, SolidJS, jQuery and others), `examples/kotlin/jars.txt` for Kotlin (Maven coordinates with each jar's SHA-256, fetched by `npm run examples:install`) and `examples/csharp/packages.json` for C# — so a library example is compiled and run like any other. A TypeScript example can be a React `.tsx` file that runs, or a Solid one that is type-checked. The site's own dependencies are unchanged.

### Changed

- **The Swift catalog can grow.** Its parity test now holds the 29 original sheets byte-identical and in their original relative order, and lets new sheets be appended, instead of pinning the catalog to exactly those 29.
- **The "most examples are run" bar is held where an example can run.** More than 80% of the examples on language and shared-concept sheets must be executed; an example on a platform sheet (a UI framework, a media player, a device API) that cannot run names the application host it needs.
