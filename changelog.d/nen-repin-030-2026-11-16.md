### Changed

- **The repository now pins nen 0.30.0.** `nen/contract.json` moves its `dependency` block from v0.21.0 to v0.30.0, the build Hatsu itself pins: nen 0.30's compatibility floor refuses any minimum under 0.30, so on any host running nen 0.30 `nen shu tools` read the old pin as `WRONG`. The block now also records the v0.30.0 bootstrap script's sha256 and the binary's per-platform sha256, checked against the release's `SHA256SUMS` and the bootstrapped binary. The pull-request readiness workflow reads the pin from the trusted base, so it moves to 0.30 for the pull requests after this one lands. nen 0.30's readiness output carries the same six conjuncts the workflow's reader expects, but since nen 0.29 a readiness placeholder check no longer reads green, so a later pull request can read `not-ready` where 0.21 read `ready` on the same checks.
- **Every test row refuses to fetch vitest from the registry.** The rows run `npx --no -- vitest`, so a checkout without `node_modules` fails rather than installing an unpinned vitest; run `npm ci` first.

### Added

- **Four focused test lanes beside `site`.** `site-ui` (src/bankai, src/ui: seven files), `site-content` (src/content, content/: all ten files, since every test imports the content model), `site-adapters` (src/adapters, src/pages, gatsby-*: three files) and `site-scripts` (serve, verify and run-examples: two files), each a fixed `vitest run` over the test files that exercise that area, so a local checkpoint runs the tests a change can move. A change to `scripts/build-offline.mts`, `scripts/readiness_ci_verdict.mts` or `scripts/consumer_trailer_ci.mts` has no focused route yet: none of them has a test. None of the lanes measures coverage: the whole suite and its coverage stay the `site` lane's.
